# booth-tap-logger（案③：スタッフが来場者のQRを読み取る）

来場者はスマホに「マイQR」（自分専用のQRコード）を表示します。各ブースのスタッフがそのQRを読み取り、「来訪・体験・購入」などのアクションをワンタップで記録します。景品引換の流れは案①（stamp-rally）と同じです。

このフォルダだけで動きます。`stamp-rally`（案①）とは、フロント、GAS、スプレッドシートを共有していません。

## 構成

```text
booth-tap-logger/
├── index.html          # 来場者：マイQR＋景品引換
├── staff.html          # スタッフ：設定（PIN・ブース選択）→ QR読み取り
├── poster.html         # 受付掲示用「マイQR」案内ポスター（印刷用）
├── css/style.css       # デザイン（イベントLPと同じ配色・フォント）
├── js/config.js        # GAS の URL（デプロイ済み・設定済み）
├── js/visitor.js       # 来場者画面
├── js/staff.js         # スタッフ画面
├── js/vendor/qrcode.js # QR生成（qrcode-generator / MIT）
├── js/vendor/jsQR.js   # QR読取（jsQR / Apache-2.0。BarcodeDetector 非対応端末でのみ読み込み）
├── images/
└── gas/                # Drive 上の GAS と同じ内容（管理用の控え）
```

- 案内ポスター：`https://obayashi-smartcity.github.io/SHOP_Logger/booth-tap-logger/poster.html`

## 当日の使い方

### スタッフ
1. `staff.html` を開き、PIN（スクリプトプロパティ `STAFF_KEY`）を入力して「読み込む」を押します。
2. プルダウンから担当ブースを選び、画面下の「このブースで読み取りを開始」を押します。カメラが起動します。
3. 来場者のマイQRを枠に写すと、アクションのボタンが表示されます。該当するものをタップすると記録されます。
   - アクションが1つだけのブース（受付など）は、読み取った時点で自動的に記録されます。
   - 同じ来場者を4秒以内に続けて読み取った場合は無視されます（二重記録の防止）。
   - 記録はいったん端末に保存してから送信します。電波が悪くても、あとで自動的に再送されます（「未送信 n件」と表示されます）。
4. 次回からは設定が保存されています。ページを開いて「カメラを起動」を押すだけで再開できます。担当を変えるときは「設定を変更」を押してください。

### 来場者
- 受付の案内ポスターのQR（またはLPのリンク）から `index.html` を開くと、マイQRが表示されます。
- 「立ち寄ったブース」の数は自動で更新されます（画面に戻ったとき、および1分ごと）。
- 景品受付で下部メニューの「景品」を開き、スタッフから伝えられる4桁のコード（`REDEEM_CODE`）を入力します。引き換えると引換券は「使用済」になります。

## ブースマスタ（スプレッドシートの booths シート）

| 列 | 内容 |
|---|---|
| boothId | 英数字のID。集計のキーになるので、当日は変更しないでください |
| boothName | スタッフ画面とログに表示する名前 |
| actions | 読み取り後に表示するボタン。カンマ区切り（例：`来訪,体験,購入`）。1つだけなら自動で記録されます。空欄の場合は「来訪」になります |
| active | チェックを外す（FALSE にする）と、スタッフ画面の選択肢に表示されなくなります |

マスタはスタッフ画面を開くたびに読み込み直されます。シートを書き換えるだけで反映され、再デプロイは必要ありません。

## 記録（logs シート）

列：記録日時、端末日時、source（`staff` / `visitor`）、visitorId、event、boothId、boothName、action、deviceId（スタッフ端末）、userAgent

| source | event | 意味 |
|---|---|---|
| staff | `visit` | スタッフがマイQRを読み取って記録した（action 列にアクション） |
| visitor | `open` | 来場者がマイQRの画面を開いた |
| visitor | `redeem_view` / `redeem` / `redeem_ng` / `redeem_dup` / `redeem_locked` | 引換画面を開いた / 引換成功 / コード誤り / 引換済み端末からの再申請 / 誤入力の上限に達した |

`summary` シートでは、ブース×アクションのクロス集計、時間帯別の記録数、来場者数、1人あたりの平均立ち寄りブース数が自動で集計されます。

## 来場者アンケート（Google フォーム）

景品引換画面を開くと、4桁コードの入力の前にアンケート（7問）が表示されます。全問を1ページに縦に並べたスクロール形式です（この画面だけはスクロールします）。`js/config.js` の `SURVEY.MODE` を `'step'` にすると、1問1画面の形式に切り替わります。回答は Google フォームに直接送信され、送信が終わるとコード入力に進みます。アンケートは1端末につき1回です。

- フォーム：Drive `SHOP_Logger0.0/booth-tap-logger/EmpoweringWOMEN 来場者アンケート（booth-tap-logger）`（[編集画面](https://docs.google.com/forms/d/11Syj4HdWvq3TQ6SU2Ethueyfw3xJBranng6GWhiH1pY/edit)）
- 設問：年齢層（単一）、性別（単一）、勤務先ビル（自由記述）、NPS（0〜10）、興味のあるジャンル（複数）、イベントを知ったきっかけ（単一）、感想・要望（自由記述）。ほかに、ログと突き合わせるための visitorId を送信します。
- 必須か任意かは画面側で制御しています（フォーム側はすべて任意）。必須は年齢層・性別・NPS・きっかけの4問です。
  未回答の必須項目があると、送信ボタンを押したときに枠を赤くし、その質問まで自動でスクロールします。
- 送信先と各設問の entry ID は `js/config.js` の `SURVEY` に設定しています。`ACTION` を空にすると、アンケートを出さずにコード入力へ進みます。
- 回答の送信は、ログにも `survey_submit` として記録されます（回答の内容は含みません）。

**注意**
- フォームの選択肢を変えるときは、`js/config.js` の `options` も同じ文言に揃えてください。文言が違う回答は、フォームに記録されません。
- 送信が成功したかどうかは、画面側では確認できません（Google フォームの仕様）。設問を変えたら、必ず一度テスト送信して、フォームの「回答」タブで記録されていることを確認してください。
- フォームの「公開済みのオプション」で、回答者が「リンクを知っている全員」になっている必要があります（現在この設定です）。
- フォームを作り直す場合は、`gas/survey-form-setup.gs` を使い捨ての GAS プロジェクトで実行し、ログに出た URL と entry ID を `js/config.js` に貼り付けます。

## デザイン

- スマホ表示を基本にしています（PCでは中央に 480px 幅で表示）。配色とフォントはイベントLPと同じです。
- 画面の構成は、ヘッダー（ブランド名と状態表示）、メイン（カード型）、下部の固定メニュー（片手で操作できる位置）の3つです。
- 4桁コードは4マスの入力欄です。数字キーボードが開き、4桁そろうまで「引き換える」は押せません。
- スマホ1画面に収まるように作っています（iPhone SE の 375×667 でも、各画面がスクロールなしで表示されます）。説明文は右上の「?」から開くシートにまとめ、初めて開いたときだけ自動で表示します。

## 注意点

- マイQRは端末のブラウザに保存された匿名IDです。ブラウザのデータを消去したり、別のブラウザで開いたりすると、別のQRになります。
- PINを5回続けて間違えると、その端末は10分間ロックされます。
- GAS のコードを変更したときは、「デプロイを管理 → 編集 → 新バージョン」で再デプロイしてください。こうするとURLは変わりません。
